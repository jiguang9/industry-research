# 评测标准

## 单用例评分（对应 cases.md 中每个用例）

每个用例按以下四个维度打分，四个维度都通过才算 `passed`；任一维度不满足则为 `failed`；因能力受限（如无联网）导致范围缩小但行为正确的记为 `partial`：

1. **边界识别**：是否正确识别了本次任务的深度（Quick/Deep）、用途（overview/client-prep/opportunity）、地区，以及是否属于本 Skill 的边界内任务。
2. **证据纪律**：正文中的关键判断是否有证据编号，事实/推断/未知是否区分，数字口径是否完整或如实标注缺失。
3. **诚实的不确定性**：证据不足、访问失败、口径冲突时，是否如实反映为 `partial`/`insufficient_evidence`/证据缺口，而不是编造结论或悄悄降低标准蒙混过关。
4. **任务可用性**：输出是否真的能被用户直接用于下一步工作（会前准备用例要有可问的具体问题，机会探索用例要有可执行的验证动作），不是泛泛而谈。
5. **五维语义验收**（不能只凭"五个标题齐全"判通过）：五维总览表与正文展开部分是否一致；收费和成本是否解释清楚（而不是只罗列收入类型）；至少一条环节间关系能否追溯到证据编号；是否出现了不适用于该行业的线性产业链、按产业链位置排序的利润断言、单一细分数据外推的行业阶段判断、或未经证实的因果结论；建议是否真的对应本次用途（overview/client-prep/opportunity），而不是套话。

## 对比评测方法（同模型、同资料、同预算）

用于横向比较"裸提示词 / 其他公开行业研究类 Skill / 本 Skill"三种条件下的产出质量。三个任务覆盖传统产业、软件服务、新兴领域各一个（可复用 cases.md 中的用例 1、5、8 或自选同等难度的任务）。

对每个任务，在同一模型、同一批可用资料、同等时间/搜索预算下分别产出结果，记录并比较：

| 比较维度 | 具体检查 |
|---|---|
| 事实与口径错误 | 数字是否有时期/地区/范围混淆、单位混用、名义/实际增长混淆等错误 |
| 证据可追溯性 | 关键判断是否能定位到具体来源；换一个人能否按图索骥核实 |
| 重要问题覆盖 | 是否覆盖了该任务本应回答的关键问题（参考 [industry-framework.md](../references/industry-framework.md) 五维） |
| 任务可用性 | 产出能否直接用于下一步工作，还是需要用户自己大量返工整理 |
| 耗时与修订量 | 产出所需时间，以及用户为了让结果可用而需要追加的修订工作量 |

**证据保留要求**：记录对照项目的 URL/commit（若为开源 Skill）或版本信息、实际配置、任务输入、产出全文或链接。有条件获取真实从业者盲评时优先于模型自评；使用模型自评时必须在结果中明确标注"模型自评"，不得混同为独立第三方评测。

## 诚实标注状态

v0.1 要求交付的是**可执行的对比方法和记录模板**（本文件 + cases.md 的记录格式）。只发布已经实际完成的对比结果；没有执行的对比不得编造分数或结论，应在 [docs/validation-report.md](../docs/validation-report.md) 中如实标注"设计完成，尚未执行"，并说明这不影响先发布一个诚实标注状态的初版。
