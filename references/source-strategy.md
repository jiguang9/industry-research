# 来源选择与中文检索方法

本文件是 [SKILL.md](../SKILL.md) 的补充说明，用于指导按问题类型选择来源，以及中文语境下的检索技巧。仅在需要更细的检索方法时读取。

## 1. 按问题类型选择来源

| 想回答的问题 | 优先来源类型 | 例子 |
|---|---|---|
| 行业官方定义、统计口径、政策 | 统计机构、主管部门、正式文件 | 国家统计局行业分类说明、部委发布的产业政策文件、行业主管部门统计公报 |
| 企业真实经营状况、财务结构 | 企业年报、招股说明书、交易所披露 | 上市公司年报"管理层讨论与分析"部分、招股书"行业与竞争"章节 |
| 产品、定价、交付方式 | 企业产品文档、服务说明、采购/招投标文件 | 官网产品定价页、政府采购网公开招标文件、SaaS 产品的服务条款 |
| 行业分类方法、细分逻辑 | 可核验的协会资料、专业研究机构公开的方法论说明 | 行业协会发布的分类标准、研究机构公开的报告摘要（不是转载的营销号总结） |
| 用户使用体验、渠道信号 | 公开评价、用户主动提供的客服/销售/访谈材料 | 应用商店评论、行业论坛讨论、用户自己提供的销售录音摘要 |
| 新事件、新变化的线索 | 新闻、财经媒体，尽量追到原始发布者 | 企业公告原文优先于财经媒体转述；监管发布优先于媒体解读 |

## 2. 来源质量由主张决定，不由来源类型单独决定

同一个来源在不同主张上的证明力不同：

- 企业官网可以证明"该企业在官网上如此描述自己的产品"，不能单独证明"该企业市场领先"或"客户满意度高"。
- 官方统计机构的数据也可能引用了外部估计或行业协会数据，遇到关键数字时要检查原始出处，不能因为发布方权威就跳过溯源。
- 财经媒体报道可以作为事件线索，但涉及具体数字时应尽量找到企业公告、监管文件等一手来源。

## 3. 避免"虚假多来源"

- 同一篇研究报告被五个公众号/媒体转载，不能算作五个独立来源；应在 `evidence.json` 的 `sources[].origin_id` 中把它们归为同一来源组。
- 只有确认了发布时间、发布主体和内容有实质差异后，才能判断为独立来源，不能仅凭 URL 或标题不同就认定独立。
- 搜索引擎摘要本身可以作为"线索"保留（`access_status: snippet_only`），但不能当作"已读原文"来支持 `fact + supported` 的主张。

## 4. 中文检索技巧

- 检索行业定义时同时尝试官方名称、常见俗称、英文对照词，例如"工业软件""工业互联网平台""Industrial Software"分别检索，交叉核对边界是否一致。
- 涉及分类/统计口径时，优先搜索"统计分类""行业标准""国民经济行业分类"等词，定位到官方文件而非二手解读。
- 涉及企业经营数据时，优先直接搜企业名 + "年报"/"招股说明书"/"上市公告"，而不是搜"XX公司 营收 多少"（后者更容易命中营销号估算）。
- 涉及近期变化时，优先加上具体时间词（如"2026年""上半年"）缩小范围，并核对文章发布日期是否落在需要的时间窗口内。
- 遇到明显的自媒体"行业深度解读"时，把其中的关键数字当作线索，尝试回溯到它引用的原始报告或统计数据，而不是直接引用二手总结。

## 5. 访问受限时的记录方式

- 付费墙/登录墙：记录 `access_status: failed`，`access_note` 写明原因（如"需要付费订阅""需要登录企业账号"），不要因此把该主张判定为"不存在"。
- 只能看到搜索摘要：记录 `access_status: snippet_only`，对应主张的 `evidence_status` 最多为 `partial` 或 `unverified`，不能标为 `supported`。
- 用户主动提供的材料：`source_type: user_supplied`，`file_ref` 填相对引用或匿名标签，不在公开产出中泄露文件真实路径或客户身份信息。
